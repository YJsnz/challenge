# 三维地图链路验证 · 2026-11-05

在 WSL 2 Ubuntu 24.04、Python 3.12.3、OpenCV 5.0.0.93、PyQt5 5.15.11 上验证。Windows 只用于编辑和 Git。构建和推理均在 WSL 中执行。

| 验证项 | 结果 |
|---|---|
| Linux 回归 | 90 项通过，32 组合成回归完成。sdist、wheel 构建和脱离源码导入通过。 |
| 点云导入 | 示意地图 43,856 点。另用上游比赛场地的真实 `RM2025.pcd` 验证导入，共 709,984 点，预览抽取 50,000 点。比赛场地点云只用于格式验证。 |
| 像素到地图的数值链路 | 61 帧模拟几何回放，已知落点的最大数值差约 `1.38e-7 m`。 |
| 标定工具 | 用 6 个模拟控制点拟合，并用 4 个不同的地面点检查。最大位置差约 `5.24e-15 m`、重投影差约 `5.93e-13 px`。这些数据只验证数值实现。 |
| 录像开头 | Warehouse_026 / Camera_0000 前 141 帧经真实模型推理。输出人员 XYZ；本段没有输出叉车轨迹。 |
| 选定录像片段 | 同视频源帧 1335–1384。使用无损 FFV1 片段，逐帧核对解码像素与源视频一致。原生 Qt 实际推理、显示和记录 50 帧；12 帧同时有人员与叉车观测轨迹。 |
| 三维导出 | 选定片段导出 94 条轨迹记录，车辆 53 条、人员 41 条。包含观测与预测状态，全部标记为示例。 |

所选录像片段用同一 YOLO11s 模型及保守分类阈值，人员 0.15、叉车 0.40。50 帧中检测输出共 53 个车辆框和 12 个人员框，计数可包含同一目标跨帧的输出。最终复测含 Qt 的处理时间约 10.4 秒，片段源帧率 30 FPS。此配置在当前 CPU 环境低于原视频帧率。
