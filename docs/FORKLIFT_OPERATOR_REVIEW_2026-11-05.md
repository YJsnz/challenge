# 叉车司机与地面行人的风险配对复核

## 原因

Warehouse_026 / Camera_0000 第 1335–1384 帧里，模型把驾驶位内可见的司机识别为人员。司机的检测框底边被投影到地面后，生成了独立的人员轨迹。第 1363 帧，这条轨迹处于失去观测状态，仍参与预测，与本车配对触发一级提示。第 1384 帧，一个横跨画面上下边缘的重复车辆框生成第二条车辆轨迹，又触发一次一级提示。

## 调整

- 为该固定机位加入 `warehouse026_front` 规则。驾驶位几何、连续关联证据和车辆图像位移同时满足时，Qt 将人员标记为“疑似司机”。已关联司机短暂缺检时，且本车仍有观测，关联最多保留 0.40 秒。出现冲突观测或候选不唯一时恢复正常配对。
- 司机检测、轨迹及原始观测保留，风险计算只排除司机与其关联叉车这一对。行人对本车、司机对其他车辆仍走原风险逻辑。司机框底边推算的坐标仍可审计，界面提示该落点仅供参考。
- 对这一机位中覆盖画面上下边缘、又几乎完整包住另一正常叉车框的超大框，跳过它的地面跟踪观测。原框保留在 JSONL，结果记录被排除的观测 ID。该规则不改变人员与叉车的检测阈值。
- 规则仅在明确配置的固定机位录像启用。用发布方 Warehouse_026 标定重新生成演示配置时自动接入；默认场景、USB 和 ROS 路径保持正常配对。

## WSL 验证

前后对照重放同一批模型观测，风险阈值与种子固定。帧号均为源录像帧号。

| 片段 | 原方案 | 调整后 |
|---|---|---|
| 正面驶近，1335–1384 帧 | 2 次一级提示，22 帧存在提示 | 0 次提示，36 帧建立或延续司机关联，排除 3 个超大重复车辆框 |
| 转弯，1385–1449 帧，独立初始化跟踪 | 2 次一级提示 | 1 次一级提示，转弯后的司机框未满足正面驾驶位规则 |
| 地面行人靠近叉车，1140–1229 帧 | 默认模型只输出人员，未形成两类轨迹 | 人员未标为司机；补测 1170–1185 帧的仓库分块预设也未检出叉车 |
| 地面人员与远处叉车同画面，0–15 帧，仓库分块预设 | 45 次人车配对评估 | 45 次评估，地面人员未标为司机 |

合成回归额外覆盖同车司机与其他叉车、地面行人与本车、离开驾驶位、短时缺检超时、静止重叠和不同分辨率。合成用例中，本车与地面行人的风险提示仍触发。录像结果为流程和个案验证，缺少人工逐帧角色标注与现场风险真值。

WSL 全量 93 项测试、32 组合成回归和安装包验证通过。原生 Qt 用正面片段重新运行 50 帧，显示“疑似司机”并记录零次提示启动。原始输入、前后结果、计数和截图在本机 `outputs/operator-validation/`。

## 启动

按[三维地图流程](MAP3D.md)用原 Warehouse_026 标定和模型生成一个新演示目录，再启动 Qt。已经生成的演示目录会继续使用其原配置。仓库实测前需要独立验证叉车角度、遮挡行人及上下车过程，正面规则当前只适用于该演示机位。
